# Factory Interface Module

> **Living document.** Read this before modifying the module. Update it in the same change whenever the trait, the error enum, or the consumers change.

**Source:** `contracts/factory-interface/` · **Crate:** `soroswap-factory-interface` 0.0.1 (`Cargo.toml:2`) · **Last verified:** 2026-09-06

## Purpose

Shared Rust crate that defines the factory's ABI once and generates the client used by other contracts. It is not deployable, it has no `[lib] crate-type` entry so it builds as a plain rlib. Both the factory and the pair depend on it, so any change to the trait or to `FactoryError` is a breaking change for two contracts at once.

## Structure

| File | Purpose |
|---|---|
| `src/lib.rs` | `SoroswapFactoryTrait`, `Spec`, and the generated `SoroswapFactoryClient`. |
| `src/error.rs` | `FactoryError` contract error enum. |

## Public surface

- **`SoroswapFactoryTrait`** (`src/lib.rs:15`): the twelve factory functions. Signatures are listed in [factory.md](factory.md); the trait is the source of truth for them.
- **`SoroswapFactoryClient`**: generated by `#[contractclient(name = "SoroswapFactoryClient")]` (`src/lib.rs:12`). This is what the pair uses to read the fee switch.
- **`Spec`**: the spec function holder for `#[contractspecfn(name = "Spec", export = false)]` (`src/lib.rs:11`). `export = false` keeps the spec out of consumers' WASM.
- **`FactoryError`** (`src/error.rs:6`): 201 `NotInitialized`, 202 `CreatePairIdenticalTokens`, 203 `CreatePairAlreadyExists`, 204 `InitializeAlreadyInitialized`, 205 `PairDoesNotExist`, 206 `IndexDoesNotExist`.

## Dependencies

- `soroban-sdk` 20.2.0 (`Cargo.toml:9`).
- Depended on by the factory (`contracts/factory/Cargo.toml:14`, used at `contracts/factory/src/lib.rs:13`) and by the pair (`contracts/pair/Cargo.toml:15`, used at `contracts/pair/src/lib.rs:4`).

## Gotchas and invariants

- `#![deny(warnings)]` at `src/lib.rs:1`. An unused import or a deprecation warning fails the build of this crate and therefore of the factory and the pair.
- The pair imports only the client, not the trait (`contracts/pair/src/lib.rs:4`). Adding a trait method forces the factory to implement it; changing an existing signature silently changes the calls the pair makes.
- The crate is referenced by path plus version (`contracts/factory/Cargo.toml:14`). Bumping the version in this `Cargo.toml` without bumping the dependency declarations breaks resolution.
- This crate is where the on chain error numbers live. Renumbering breaks every off chain decoder.

## Testing

No tests in this crate. It is exercised indirectly through the factory and pair suites.
